# 上下文查看

配套后端：CPA QoL `0.1.0-rc.7`。入口为 `management.html#/monitor` 的「请求详情」卡片。

## 会话视图与共享存储

默认列表按下游 Key 和会话 ID 归并，同一会话只显示一条。正文依据消息 ID、内容版本和请求内的先后关系，整合完整历史与增量内容，重复项仅展示一次。没有先后证据的部分按首次出现排序；顺序冲突会提示，不假装还原完整分支。

切换「原始请求快照 / JSON」仍可逐次检查原始请求。后端将重复消息块只存一份，以引用保留每次请求，过期时只删除不再使用的块；因此整合展示不需要牺牲原始数据。旧记录没有保存 Key / 会话关联时不能猜测合并，但同样参与存储去重。

工具调用以参数字段、命令/代码、执行结果展示，结构化结果中的文本使用 Markdown。识别 Codex 的 `agent_message`、`additional_tools` 等类型；加密思考和压缩状态只提示不可解密，原始内容仍保留。

## 记录和查看

- 右上角「上下文记录：开启/关闭」打开配置窗口，调整记录开关、保留时长并查看占用空间。安装默认关闭；升级保留已保存的设置。
- 旁边「查看上下文」打开现有快照列表。列表标题展示下游 Key 前六位和模型；旧记录缺少 Key 时明确显示未知。
- 请求明细最后一列「查看」打开同一下游 Key、同一 CPA 会话标识下所有尚未过期的快照。不受当前统计时间段限制，正文仍逐条按需拉取。
- 默认使用可读视图，按原顺序展示 system prompt、用户/助手消息、工具调用及结果。可切回 JSON；未知结构保留原始 JSON，不擅自丢弃。
- 「客户端标识」展示客户端自行上报的 User-Agent、Originator 和可选设备值哈希。没有上报就显示未知；它不是可信硬件指纹，会话 ID 也不等于设备 ID。

## 数据边界

只记录请求输入中实际存在的内容，不包含该请求新生成的回复。后续输入可能携带之前的回复，但增量请求、过期快照、未开启记录时的内容无法补齐。多个请求共享的是会话快照列表，不是凭时间推断的单个事件关联；不同 Key 严格分组，CPA 的派生提示词亲和 ID 不作为可靠会话标识。旧快照无法补出从未保存的 Key 或设备信息。

使用 `react-markdown` + `remark-gfm` 渲染 Markdown，禁止原始 HTML 和自动加载图片。大文本按 64 Ki 字符分段，可读块按 20 个分页，避免一次创建大量 DOM。接口、隐私与保留规则见 [QoL API](https://github.com/x3zvawq/Cli-Proxy-API-Plugin-QoL/blob/main/docs/api.md#record-request-context-rc5)。
